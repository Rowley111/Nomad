# Nomad Mobile

React 18 + Vite 5. Астана, русский интерфейс, KZT. Главный экран — оценщик по сохраняемому прайсу и справочнику из Excel; также доступны склад, история продаж, ремонты, касса и сотрудники. По умолчанию данные локальные. Для общей базы подготовлен отдельный защищённый FastAPI/PostgreSQL API с миграциями и переносом старых данных. Онлайн-мониторинг OLX не подключён.

## Запуск на Windows

Установите Node.js 22 LTS или новее. В PowerShell из папки репозитория:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте адрес из терминала. Для iPhone в той же сети используйте IP ноутбука и порт 5173 (разрешите его в Windows Firewall). Данные каждого адреса и браузера отдельные.

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run preview
```

Браузерные проверки:

```powershell
npx.cmd playwright install chromium
npm.cmd run test:ui
```

В Linux проверенная конфигурация использует /usr/bin/chromium. Для другого пути задайте CHROMIUM_PATH; если системного Chromium нет, используется браузер Playwright. Проверяются 1440 px и 390 px. Эмуляция размера не заменяет проверку настоящего Safari на iPhone.

## Рабочий сценарий

1. Оценщик открывается с пустым выбором модели. Выберите устройство, память и физическую ОЗУ Android: сохранённый собственный прайс имеет приоритет; при его отсутствии используется подходящий черновой ориентир Excel. Повторно загружать Excel не нужно.
2. В «Прайс и источники» можно один раз сохранить проверенный ориентир для точной конфигурации, указав автора, дату, базовое состояние, комплект и пояснение. Для конфигурации без данных цена не выдумывается. Непроверенные критические риски и черновой Excel скрывают безопасный максимум закупа.
3. «Сохранить оценку» сохраняет снимок, но не создаёт закупку. «Оформить закупку» требует фактическую сумму; превышение максимума/риски требуют причины. Закуп 0 допустим.
4. На складе продажа требует фактическую выручку, прямые расходы, способ оплаты и дату сделки. Повторная продажа отвергается. Исправление — возврат с причиной и новая продажа, события сохраняются. Плановую цену и примечание можно менять с журналом.

Контроль: A35 5G 8/128, хороший экран/корпус, коробка, следы от чехла уже учтены; сохраните ориентир 89 000 ₸. При наценке 25% рассрочка 111 250 ₸; при цене продавца 50 000 ₸ и нулевых расходах ожидаемая разница 39 000 ₸. Это ориентир владельца, не рыночная сделка. Прибыль показывается до налогов и общих расходов.

Серьёзные дефекты переводят в ручную диагностику даже в сценарии ремонта. Автоматической оценки повреждённой матрицы/жидкости нет. Политика магазина редактируется; комиссия банка не равна наценке рассрочки. Каталог редактируется через конструктор в настройках; расширенный JSON-редактор также сохранён; неподтверждённые Android-конфигурации нужно сверить с маркировкой/официальными источниками.

## Хранение и резервные копии

Рабочий ключ: `nomad-workspace-v2`, schemaVersion 2. Старый массив `nomad-inventory-v1` переносится один раз с копией `nomad-inventory-v1-backup-before-v2`; исходный ключ не меняется. Вся прежняя карточка сохраняется. Старый статус «Продан» не подтверждает сумму и дату и не попадает в реализованные показатели. Ошибка чтения не подменяет склад демотоваром.

Перед каждой записью предыдущая версия сохраняется в `nomad-workspace-v2-before-write`. Это аварийная локальная копия, а не независимый бэкап. Регулярно скачивайте полный JSON в настройках. Восстановление проверяет схему и показывает количество записей до подтверждения полной замены. Для переноса с localhost/другого устройства используйте этот файл: доступ к хранилищу другого адреса автоматически невозможен. Не работайте параллельно в нескольких вкладках локального режима.

Прайс импортируется отдельно через CSV/JSON с предпросмотром и отчётом ошибок. Выгрузите существующий прайс как образец; CSV UTF-8, разделитель `;`, заголовки английские. `source=owner`, `market=Астана`, `currency=KZT`, `channel=store-cash`; состояния ideal/good/worn, SIM physical/esim/other. Повторный ключ обновляет запись с историей. Полная копия JSON — для склада и оценок, CSV склада не является полной резервной копией. Экспорт экранирует формулы.

Без `VITE_API_URL` действует прежний локальный режим: посетители фронтенда видят своё браузерное хранилище, между устройствами оно не синхронизируется. С настроенным адресом API нужен вход; рабочие записи сохраняются на сервере после проверки прав и ревизии. `DATABASE_URL` задаётся только серверу. Не помещайте рабочие данные и секреты в исходники или `VITE_*`. [Подключение PostgreSQL, миграции и перенос](docs/DATABASE_MIGRATION.md).

## Render и откат

Существующий Render Static Site сохраняется: Build Command `npm ci && npm run build`, Publish Directory `dist`. Перед обновлением скачайте полный JSON на действующем адресе. FastAPI работает отдельным Web Service, не внутри Static Site. Настройки контейнера/API и безопасная последовательность миграции описаны в [DATABASE_MIGRATION.md](docs/DATABASE_MIGRATION.md); [render-api.yaml](render-api.yaml) — пример для ручной настройки, без создания PostgreSQL и платных ресурсов. Наличие переменной `DATABASE_URL` само по себе не переносит записи. Фактическая публикация и выполненные проверки отмечаются в [CHECKS.md](docs/CHECKS.md).

Откат фронтенда — предыдущий успешный deploy в Render либо revert merge-коммита. V1 оставлен для старого интерфейса, но он не содержит новых v2-сделок: перед откатом сохраните полный v2 JSON. Не очищайте localStorage. Этапы, ограничения и результаты: docs/IMPLEMENTATION_PLAN.md, docs/DATA_SOURCES.md, docs/CHECKS.md.

## Применение подготовленного patch владельцем

Если публикация из среды заблокирована правами GitHub, скачайте `nomad-stage1.patch`. В своей существующей копии репозитория сначала проверьте `git status` и сохраните чужие незакоммиченные изменения. При чистом состоянии:

```powershell
git fetch origin
git switch -c feature/persisted-valuator-stage1 origin/main
git am C:\путь\к\nomad-stage1.patch
npm.cmd ci
npm.cmd test
npm.cmd run lint
npm.cmd run build
git push -u origin feature/persisted-valuator-stage1
```

Если `git am` сообщает конфликт, исправьте его и выполните `git am --continue`; для отмены только этой операции — `git am --abort`. Затем откройте Compare & pull request на GitHub: base `main`, compare `feature/persisted-valuator-stage1`. Не объединяйте без проверки и резервной копии данных. Сам patch не публикует сайт.

## Справочник скупки владельца и новый интерфейс (04.11.2026)

На главном экране «Подключите ваш прайс телефонов» выберите исходный `Nomad_Mobile_Price_List.docx` или подготовленный JSON формата `nomad-owner-guide`. Укажите дату редакции документа, просмотрите отчёт и подтвердите сохранение. Документ читается в браузере: никакого OLX, платного ИИ и передачи файла сторонним сервисам. После этого достаточно выбрать модель и память — предварительная скупка появится автоматически и сохранится при перезагрузке.

По указанию владельца к диапазону скупки iPhone применяется снижение **30 000 ₸**, к Android — **0 ₸**. Оба значения редактируются в настройках; изменение действует на новые расчёты, не на старые снимки и фактические закупы. Снижение применяется один раз к скупке из документа, а не к витрине. Например, справочная скупка iPhone 13 128 ГБ 90–105 тысяч превращается в 60–75 тысяч до диагностики и дополнительных расходов. Консервативная выручка берётся из нижней границы быстрой продажи документа.

Предварительное предложение видно и до проверки устройства. «Максимальный закуп» при критических неизвестных остаётся недоступным; закуп с принятием рисков требует причины. При серьёзных дефектах копирование предложения блокируется. Расширенные проверки и расходы находятся в раскрываемом блоке «Комплект, диагностика и расходы».

Полный коммерческий прайс не включён в исходники или публичные assets. Каждый браузер импортирует его один раз; для переноса используйте полную резервную копию JSON. Из 110 строк предоставленного документа 101 сопоставлена с каталогом; 9 требуют уточнения модификации/ОЗУ или официального подтверждения конфигурации. Они перечисляются в предпросмотре и не получают выдуманной замены. Согласованные исторические закупы и индивидуальные случаи документа не импортируются как универсальные новые цены.

Оригинальный знак извлечён в SVG из предоставленного `Logobook.pdf`, страница «Цветовое решение». Навигация оформлена в тёмно-синем; фирменный сине-фиолетовый `#292970` используется для акцентов. Источники логотипа и коммерческий DOCX целиком в Git не включены.

## Автоматическая настройка по персональной ссылке

По запросу владельца доступна настройка без скачивания файлов. Откройте выданную персональную ссылку на действующий сайт: приложение расшифрует подготовленный справочник на устройстве, проверит строки и сохранит недостающие конфигурации через обычный механизм резервной копии. Склад, ручные цены, изменённые записи справочника и торговая политика сохраняются. Повторный переход не дублирует импорт; строки на уточнение доступны в оценщике.

Публичный файл `public/setup/<id>.json` содержит только AES-256-GCM шифротекст. Ключ не входит в Git, HTML, VITE\_\* или localStorage: он передаётся владельцу в URL-фрагменте и удаляется из адреса до сетевого запроса. Приложение не отправляет фрагмент серверу. Полная ссылка позволяет открыть прайс её обладателю; это персональная ссылка настройки, а не одноразовая серверная сессия или авторизация общей базы. Можно настроить ноутбук и iPhone той же ссылкой: данные устройств остаются отдельными.

Для подготовки нового контейнера разработчиком: `node scripts/create-owner-setup.mjs <приватный JSON> <путь ссылки ВНЕ репозитория>`. Генератор пишет в Git только зашифрованный контейнер, полный URL сохраняет в указанный приватный файл и не печатает в терминал. Не добавляйте этот приватный файл или полный URL в PR, CI, логи и публичные инструкции. Для отзыва ссылки нужно удалить контейнер с хостинга; ранее сохранённые локальные данные этим не удаляются.

## Ремонты: заказы, материалы и заработок

В меню добавлен раздел **«Ремонты»**. В нём три вкладки: «Заказы», «Отчёт по ремонтам» и «Справочники».

1. В «Справочниках» добавьте свои типы ремонта и, при необходимости, шаблоны материалов с единицей измерения и себестоимостью. Изменение шаблона не переписывает уже учтённые расходы.
2. Нажмите «Новый ремонт», укажите устройство, тип работы, дату приёма и согласованную стоимость (необязательно). Устройство можно назвать свободно, независимо от наличия цены в оценщике.
3. В заказе добавляйте использованные материалы: количество × цена единицы. Отдельно заносите доставку, оплату подрядчику и прочие прямые расходы. У каждой строки своя дата расхода.
4. Полученные деньги записывайте через «Подтвердить оплату»: доступны авансы и частичные платежи. Возврат клиенту — отдельная операция с причиной, не больше ранее полученной суммы. Повторное подтверждение с тем же идентификатором не удваивает деньги.
5. Статусы: принят, в работе, готов, выдан, отменён. Выдача не создаёт оплату автоматически. Отмена не удаляет реальные оплаты и затраты. Данные заказа/смету можно менять с историей; ошибочный расход исключается с причиной, затем правильная строка добавляется заново.
6. «Отчёт по ремонтам» и «Аналитика → Ремонты за период» показывают выбранные даты, текущую неделю/месяц, прошлый месяц или всё время. График группируется по неделям (понедельник–воскресенье) или месяцам; столбцы можно выбирать мышью/клавиатурой. Есть CSV заказов и отчёта.

Заработок в этом разделе = фактические поступления − возвраты клиентам − материалы − другие прямые расходы. Например, 18 000 − 2×3 000 − 1 000 = 11 000 ₸. Это денежный результат до налогов и общих расходов, включая авансы; смета сама по себе не увеличивает доход. Период определяется датой оплаты/расхода, а не датой создания заказа. Поэтому месяц покупки материалов до получения оплаты может иметь отрицательный результат. Продажи техники остаются в отдельном представлении «Склад и продажи» и не смешиваются механически с кассовым отчётом ремонтов.

Материальный справочник хранит шаблоны, а не остатки отдельного склада запчастей: автоматического списания складских остатков нет. Для каждой работы сохранены название материала, фактическая себестоимость и история, даже если шаблон позже изменился.

### Хранение ремонтов и обновление

В локальном режиме серверная база не требуется: данные сохраняются в том же `nomad-workspace-v2` с добавочной `repairSchemaVersion: 1`, массивами `repairOrders`, `repairTypes`, `materialCatalog`, `repairEvents`. Перед первым дополнением старого рабочего пространства исходный JSON сохраняется в `nomad-workspace-v2-before-repairs-v1`; склад, прайс, оценки, продажи и настройки не подменяются. В настроенном облачном режиме эти же записи входят в общий workspace PostgreSQL.

Полная JSON-копия в настройках включает ремонты, оплаты, материалы и журнал. При локальном восстановлении видно количество этих записей и предупреждение, если старая копия их не содержит: подтверждение **полностью заменяет** локальное рабочее пространство. Для общей базы используется отдельный административный перенос с предпросмотром и объединением без перезаписи конфликтующих существующих записей. Доступ к данным другого адреса/устройства автоматически невозможен: используйте полный JSON. Регулярные независимые резервные копии нужны в обоих режимах.

Проверки: `npm.cmd test` запускает расчёты оценщика, расчёты ремонтов и проверку переноса/резервных копий; `npm.cmd run test:ui` включает основные сценарии ремонта на 1440 и 390 px. Новые зависимости не добавлялись.

## Убытки и отрицательный итог

В «Ремонты → Убытки» можно ввести **−5000** (или 5000), дату и причину: запись всегда означает потерю **−5 000 ₸**, не доход. При необходимости выберите заказ; общий убыток можно сохранить без заказа. Запись учитывается по дате потери в недельном/месячном отчёте и графике, а связанная с заказом — также в его результате. Это одна операция: повторное подтверждение не удваивает сумму.

Убытки показываются отдельной строкой, отрицательный общий результат выделяется красным и подписью «В минусе». Например, при результате ремонта 11 000 ₸ и отдельном убытке 5 000 ₸ останется 6 000 ₸; если других поступлений нет, итог будет −5 000 ₸. Не дублируйте убытком уже внесённые материалы, расходы и возвраты. Обычные оплаты/материалы продолжают принимать только неотрицательные суммы.

Ошибочную запись можно исключить через «Исправить запись» с причиной: история сохраняется, деньги не прибавляются как новое поступление. Доступны CSV убытков, обновлённый CSV отчёта и полная JSON-копия. Старые данные без `repairLosses` продолжают работать; существующие записи не подменяются и не заполняются демонстрационными минусами. При восстановлении старой копии явно показано отсутствие убытков и полная замена текущих данных.

После объединения прежнего каталога и Excel встроено 1 333 модели смартфонов и планшетов. Сам Excel содержит 1 187 моделей, 2 675 вариантов памяти и 40 брендов. Большинство конфигураций Excel справочные и требуют проверки точного SKU; наличие строки не означает официального подтверждения памяти или цены. Исчерпывающий каталог всех телефонов мира не заявляется. Источники прежней проверенной подборки: [Samsung/Google](docs/CATALOG_SAMSUNG_GOOGLE.md), [Xiaomi/Redmi/POCO/OPPO и другие](docs/CATALOG_XIAOMI_BBK.md), [остальные бренды и iPad](docs/CATALOG_OTHER_TABLETS.md).

В Настройках нажмите «Добавить модель»: введите бренд, точное название (4G/5G отдельно), смартфон/планшет, Wi-Fi/Cellular, память и физическую ОЗУ Android. Для Apple ОЗУ не подставляется. Добавляйте только реально проверенные варианты; виртуальное расширение ОЗУ не суммируется с физической памятью. Редактирование модели защищает используемые прайсом конфигурации и SIM. Существующие данные и исторические снимки не переписываются.

«Настроить прайс» открывает «Мои цены скупки и продажи». Один раз сохраните собственные суммы или диапазоны и автора. После выбора устройства оценщик подставляет их автоматически. Средний ориентир — середина вашего диапазона, не рыночная медиана. Быстрая продажа следует текущей политике магазина. Новый тип источника owner-buy хранится отдельно от owner-guide (импортированного документа): снижение iPhone из документа к собственным ценам не применяется. CSV/JSON сохраняют тип источника, диапазоны и историю.

Текущая ревизия каталога — 2. Локальный каталог дополняется один раз с резервной копией `nomad-workspace-v2-before-catalog-v2`; прежняя копия v1 сохраняется. Ваши модели, настройки, цены, склад и ремонты сохраняются. В существующей общей базе дополнение применяет администратор: Настройки → «Добавить готовый каталог»; это обычное защищённое сохранение с контролем ревизий. Новая SQL-миграция для расширения JSONB-каталога не требуется. Подключение владельца к PostgreSQL этой задачей не выполняется без серверного доступа.


## Встроенный справочник Excel

Из `Nomad_Mobile_Phone_Database.xlsx` включены все 2 675 вариантов. Числовые ориентиры есть у 2 618 вариантов, у 57 цена отсутствует. В самой книге все заполненные цены помечены как **черновой расчёт, рынок не проверен**. Приложение показывает это основание, дату расчёта 04.11.2026 и отсутствие даты проверки рынка; OLX не опрашивается. Ориентиры не становятся подтверждёнными сделками или рыночной медианой. Скупка у некоторых специальных моделей отсутствует и не заменяется нулём.

Используются сохранённые числовые результаты формул Excel. Поправки книги за память, возраст и ликвидность, а также снижение iPhone из отдельного DOCX повторно к ним не применяются. Сохранённый собственный прайс остаётся приоритетным: A35 8/128 с вашим ориентиром 89 000 ₸ сохраняет рассрочку 111 250 ₸. Сам Excel для A35 содержит другие предварительные значения: витрина 88 000 ₸, продажа 80 000 ₸, быстрая продажа 72 000 ₸, скупка 39 000–52 000 ₸; безопасный максимум по этим непроверенным данным недоступен.

Общие строки справочника включены в публичный сжатый модуль; частный DOCX-прайс и ключ персональной ссылки туда не добавлены. Цены Excel не копируются целиком в localStorage. Происхождение, точные количества, ограничения и воспроизводимая конвертация: [WORKBOOK_DATA.md](docs/WORKBOOK_DATA.md).

## Продажи по датам и локальное восстановление

Раздел «Продажи» показывает фактические сделки за выбранные даты, день, неделю или месяц, поиск и CSV. Дата сделки отделена от даты регистрации. Возврат остаётся отдельным событием; история не зависит только от текущего статуса или наличия карточки на складе. Старый статус «Продан» без суммы и даты показан отдельно: факты нужно подтвердить вручную, плановая цена не выдаётся за выручку.

В локальном режиме после основной записи дополнительно сохраняются минимальные факты продаж и возвратов в `nomad-sales-journal-v1`. Это запасная копия в том же браузере, не независимое облачное хранилище. Если история пропала, откройте **Настройки → «Проверить локальные копии продаж»**: сначала показываются найденные сделки, ошибки и конфликты, затем доступно подтверждение восстановления. Повторное восстановление не дублирует сделки; противоречащие текущим данные не заменяются автоматически. Старые карточки без фактов продажи можно вернуть отдельно как неподтверждённые.

Проверяются только известные ключи и копии этого адреса в этом браузере. Наличие продажи A35 у владельца нельзя подтвердить из среды разработки; очищенное хранилище или записи другого устройства/адреса автоматически недоступны. Полная JSON-копия остаётся основным способом резервирования и переноса. Ошибка дополнительного журнала не отменяет уже сохранённую основную операцию и показывается предупреждением.

## Мастера, клиенты и сотрудники

У ремонта можно указать мастера, имя клиента, телефон строкой с сохранением `+7` и примечание. Эти поля необязательны, доступны для поиска и входят в полную копию и CSV ремонта. Копии содержат контактные данные: храните их приватно.

В «Сотрудниках» добавляйте и редактируйте имена, должности и необязательные телефоны; вместо удаления сотрудника можно архивировать. Активные сотрудники предлагаются при выборе мастера и денежных операциях. Исторические имена и должности в операциях сохраняются после изменения справочника. Этот справочник не создаёт аккаунты входа и не выдаёт серверные права.

## Касса и банк

Новый учёт начинается с **0 ₸** на обоих счетах, без демонстрационных денег. В «Касса и банк» выбирайте поступление, расход или перевод, сумму, дату, категорию, причину и при необходимости сотрудника. Есть категории для материалов, расходников, коммунальных платежей и зарплаты; справочник редактируется и архивируется. Отрицательный ввод расхода нормализуется один раз, отрицательный остаток выделяется. Перевод уменьшает один счёт и увеличивает другой без увеличения общего дохода. Взнос собственника показан отдельно от дохода.

Доступны история, выбор периода, группировка, CSV и исправление ошибочной операции с причиной: исходная запись остаётся в журнале. Денежные операции содержат снимки категории и сотрудника. Повтор операции и повтор импорта полной копии не создают второе движение. Это ручной денежный журнал: банковский API не подключён; движения по счетам не равны прибыли. Продажи и ремонты не создают кассовые записи автоматически, старые сделки не загружаются как деньги в новой кассе. Учитывайте фактическое движение один раз и не дублируйте его при расчёте результата сделки.

Добавлены `cashSchemaVersion: 1`, дата начала, счета, категории, сотрудники, операции и события внутри прежнего schemaVersion 2. Перед первым локальным дополнением сохраняется `nomad-workspace-v2-before-cash-v1`. Полный JSON включает эти данные; восстановление старой копии предупреждает об отсутствии кассы и полной замене. В старой общей базе учёт с нуля начинает администратор отдельной кнопкой; сотрудники не меняют счета, категории и справочник сотрудников. Новая SQL-миграция не требуется: поля хранятся в существующем JSONB. Серверному контейнеру нужен `npm ci --omit=dev` для общей проверки справочника и расчётов.

Без настроенного `VITE_API_URL` все эти рабочие данные по-прежнему локальные. Доступ к production API/DATABASE_URL этой среде не предоставлен: подключение общей базы и перенос записей владельца не объявляются выполненными. Для подключения используйте [DATABASE_MIGRATION.md](docs/DATABASE_MIGRATION.md); секреты задаются только серверу.
