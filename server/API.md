# API общей базы

Все рабочие маршруты требуют `Authorization: Bearer <token>`. Токен возвращается только после входа; хранить его в памяти клиента. JSON не содержит URL базы или паролей. Ошибки имеют `detail` на русском языке. CORS разрешает только точные адреса `FRONTEND_ORIGIN` (через запятую).

- `GET /api/health` → `{ "status": "ok" }`, без доступа к рабочим данным.
- `POST /api/auth/login` `{username,password}` → `{token,user:{username,role}}`.
- `GET /api/auth/me` → `{username,role}`.
- `POST /api/auth/logout` → `{ok:true}`; отзывает серверную сессию.
- `GET /api/workspace` → `{state:null|<полный JSON schemaVersion:2, mode:local>,revision:0|N}`. `mode:local` внутри переносимого JSON — формат совместимости, а не режим хранения сервера.
- `PUT /api/workspace` `{state,revision,operationId}` → `{state,revision}`. `operationId` — уникальная стабильная строка для повтора одного сохранения. Несовпавшая ревизия → 409. Сервер не перезаписывает более новые данные. Сотрудник не может менять прайс, каталог, политику или переписывать историю. Проверка доменных данных выполняется общим Node-модулем.
- `POST /api/import/preview` `{state}` → `{previewId,revision,report}`. Только администратор. Отчёт содержит `added`, `duplicates`, `conflicts`, `totalAdded`; записи с конфликтами сохраняются из общей базы. Подготовленный результат действует 30 минут и привязан к пользователю/ревизии.
- `POST /api/import/commit` `{previewId,operationId}` → `{state,revision,report}`. Только администратор. Изменившаяся общая база требует нового предпросмотра (409). Повтор того же файла не создаёт дубликатов.
- `GET /api/audit` → `{events:[{id,action,username,at,revision}]}`, только администратор; снимки резервных версий не выдаются публично.

Первого администратора создаёт серверная CLI `python -m server.cli create-admin`. Публичной регистрации нет. Истечение сессии возвращает 401. Максимальный JSON-запрос — 5 MiB.


## Поля рабочего пространства и общая проверка

Формат остаётся `schemaVersion: 2`, данные хранятся в существующем JSONB. Текущий каталог имеет `catalogRevision: 2`. Ремонты могут содержать необязательные `masterName`, `clientName`, `clientPhone`, `clientNote`; отсутствие этих полей у старых заказов допустимо. Телефон сохраняется строкой.

Касса добавляет необязательный совместимый блок: `cashSchemaVersion: 1`, `cashStartedAt`, `cashAccounts`, `cashCategories`, `employees`, `cashTransactions`, `cashEvents`. Старое пространство без блока допустимо; частичный некорректный блок отвергается. Начало учёта создаёт администратор, начальные остатки нулевые. Сотрудник может проводить разрешённые денежные операции, но не менять счета, категории, сотрудников и дату/версию начала учёта. Справочник сотрудников не создаёт пользователей авторизации.

Денежные операции сохраняют `operationId` и снимки категории/сотрудника. Существующие строки не переписываются: исключение ошибочной операции требует отдельного события с причиной. Импорт использует `operationId` как дополнительный ключ дубликата; конфликт сохраняет текущую строку, связанные события пропущенной операции не прикрепляются к другой записи. События продаж/возвратов и их фактические суммы/закупочные снимки также проверяются сервером; плановая цена не подтверждает выручку.

Серверный worker использует те же правила 1.3.0, что браузер: точный сохранённый прайс приоритетен, затем доступен встроенный черновой источник `workbook-reference`. Он не является рыночной котировкой и не выдаёт безопасный максимум закупа. Для проверки используется существующий `fflate`: после установки Node выполните `npm ci --omit=dev` в корне репозитория; Dockerfile уже включает эту установку. Производственные данные и секреты не входят в статический справочник. Новой Alembic-миграции для этих добавочных JSON-полей нет.
