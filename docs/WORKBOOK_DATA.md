# Справочник из Nomad_Mobile_Phone_Database.xlsx

Источник — переданный владельцем Excel-файл. Его ячейки прочитаны как данные; формулы, макросы, внешние ссылки и текстовые указания из книги не исполняются. Полный XLSX в Git не включён. В публичном модуле находятся только общие модели, конфигурации и редакторские ориентиры; имён клиентов, контактов, сделок и персональных данных в извлечённых листах не обнаружено. Ранее полученный частный DOCX-прайс не изменяется.

## Что фактически содержится в книге

| Показатель | Количество |
| --- | ---: |
| Модели | 1 187 |
| Строки вариантов памяти | 2 675 |
| Бренды | 40 |
| Варианты с числовым ориентиром б/у | 2 618 |
| Варианты без цены | 57 |
| Варианты со стартом/потолком скупки | 2 548 |
| Модели с базовой редакторской ценой | 1 158 |
| Модели со ссылкой на спецификацию | 61 |

Сам лист «О базе» обозначает все базовые цены как редакторские оценки: текущие объявления для каждой строки не проверялись. Все 2 618 заполненных строк имеют статус «ЧЕРНОВОЙ РАСЧЁТ — рынок не проверен». Поля ручной цены конкретной конфигурации, даты её проверки и источника (`Y`, `Z`, `AE`) пусты во всех строках. Поэтому данные не являются подтверждёнными продажами, котировками OLX или свежей рыночной статистикой.

Дата расчётного снимка — **2026-11-04**. Она хранится в `calculatedOn`, а `checkedOn` цен остаётся `null`. Даты проверки спецификаций находятся отдельно в `specCheckedOn`. Ссылка `source` относится к характеристикам устройства, а не доказывает его цену. `olxSearchUrl` — сформированная ссылка поиска, без получения объявлений.

## Память и конфигурации

- 2 487 строк помечены «Справочно: точный SKU сверить».
- 172 строки Apple содержат накопитель, но физическая ОЗУ намеренно не заполнена.
- 16 строк имеют отметку книги «RAM/ROM: официальный источник».
- Эти отметки и URL сохранены как происхождение данных книги; новая поштучная официальная проверка всех моделей этой конвертацией не выполнялась. В частности, запись книги «модель подтверждена» сама по себе не превращает её в подтверждённый приложением SKU.
- Всего 75 вариантов принадлежат 35 складным/специальным моделям. У 70 из этих вариантов есть ориентир продажи, но скупка оставлена пустой. `manualDiagnosis` берётся из отдельного флага модели; исходный текст требования осмотра также сохранён в `diagnosisNote`.
- Две физические величины ОЗУ дробные: BlackBerry Bold 9900 — 0,75 ГБ, HTC Desire 816 — 1,5 ГБ. Они не округляются до выдуманной целой ёмкости.
- Повторов `variant_id`, `model_id`, пары бренд/название модели и точной строки бренд/модель/накопитель/ОЗУ нет. Соответствие каждой строки её модели проверено.

Пустая ячейка или пустой кеш формулы становится `null`, а не нулём. В книге 19 вариантов с настоящими кешированными нулями старта и потолка скупки; они сохранены как `0`, что означает нецелесообразность закупа по сценарной политике книги, а не отсутствие цены телефона.

## Конвертация и воспроизводимость

```powershell
python scripts/convert-phone-workbook.py "C:\path\Nomad_Mobile_Phone_Database.xlsx"
```

Результат: `src/data/workbook-reference.js`, экспорт `workbookReference`. Требуется только стандартная библиотека Python. По умолчанию создаётся детерминированный идентификатор из SHA-256 файла; повторная конвертация того же файла даёт тот же набор ID и содержимое. Путь к исходному файлу и данные окружения в результат не записываются.

Конвертер использует сохранённые значения **39 845 формульных ячеек**, без собственного расчёта формул Excel. `G`–`N` присутствуют как формулы во всех строках каталога; числовой кеш есть у 2 618 строк. Исходные суммы уже учитывают гипотезы книги о памяти, ОЗУ, возрасте, ликвидности и округлении. Применять те же надбавки или скидки второй раз нельзя. Политика и коэффициенты книги сохранены как данные происхождения, они не заменяют настройки магазина автоматически.

Пример контроля: Samsung Galaxy A35 5G 8/128 в книге имеет ориентир б/у 80 000 ₸, витрину 88 000 ₸, быструю продажу 72 000 ₸ и диапазон скупки 39 000–52 000 ₸. Ранее сохранённый владельцем ориентир витрины 89 000 ₸ должен иметь приоритет, без подмены этим новым редакторским числом.

Декодированные данные полного справочника занимают 3 489 768 байт. Для доставки они сжаты gzip с фиксированным timestamp и закодированы base64: gzip — 166 247 байт, весь JS-модуль — 221 989 байт. Это **сжатие публичных данных, не шифрование и не защита коммерческих секретов**. Модуль восстанавливает тот же объект через уже используемую зависимость `fflate`; неизменный экспорт — `workbookReference`.

Справочник предназначен для статического источника данных. Не следует копировать все декодированные строки вместе с повторяющимися примечаниями в каждую запись localStorage: рабочее состояние, `before-write` и резервные копии могут переполнить квоту браузера. В рабочем состоянии достаточно лёгкого каталога/ID и действительно изменённых владельцем цен.

## Выполненные проверки конвертера

- Конвертация исходного файла завершилась: 1 187 моделей, 2 675 вариантов.
- Проверены связи/уникальность ID, конечные неотрицательные числа, положительная память и порядок диапазонов.
- Пустые цены/даты и отсутствующая Apple RAM сохранены; реальные нулевые скупки не подменены.
- `python -m py_compile scripts/convert-phone-workbook.py`, ESLint модуля и `git diff --check` выполнены успешно.
- `pytest server/tests/test_workbook_converter.py`: 4/4 успешно на синтетическом XLSX без частного исходного файла. Проверены кеш формул без их выполнения, различие blank/0, дробная RAM, даты Excel, повторные/осиротевшие ID и детерминированная конвертация без пути исходного файла.
- Распакованный в Node объект глубоко равен исходному объекту до сжатия. Повторная конвертация даёт побайтно одинаковый модуль; gzip не меняет ни суммы, ни `null`, ни происхождение данных.

Генерация файла сама по себе не означает загрузку в рабочую PostgreSQL владельца или проверку рынка. Эти действия отражаются отдельно в документации интеграции и результатах API/UI-проверок.
