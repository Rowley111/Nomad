# План реализации

Исходная версия: GitHub main 7171daef6fb4c35cfcc2b68c99b37fe053699a23. Получена через GitHub API: git clone блокируется недоступным прокси. AGENTS.md в корне отсутствует. Существующие данные — массив nomad-inventory-v1; ошибки чтения прежде подменялись стартовым товаром. Исходная сборка: установка npm ci запущена; результат будет записан в CHECKS.md.

1. Этап 1: отдельные каталог, прайс, детерминированный движок и версионированное локальное хранилище; оценка → подтверждённая закупка; фактическая продажа; полная резервная копия и проверяемый импорт; тесты и адаптивный интерфейс. Не подменять старые записи демотоваром.
2. Этап 2: разрешённые источники, импорт объявлений и анализ сопоставимости; не называть ручной прайс онлайн-мониторингом.
3. Этап 3: FastAPI/PostgreSQL, защищённые сессии и роли, серверная валидация, идемпотентный перенос. Отдельные ресурсы Render после согласования инфраструктуры. Общая база до защиты не публикуется.

Этапы 2–3 не являются условиями работоспособности этапа 1. Production и main не изменять; итоговый PR требует проверки владельца.

## Результат этапа 1
Реализованы оценщик по точному сохранённому прайсу, объяснение политики, диагностические ограничения, сохранённые снимки, подтверждённые закупки и фактические продажи с журналом и возвратами, миграция v1 с резервной копией, CSV/JSON прайса и полная JSON-копия. Каталог редактируется без правок кода; часть Android-конфигураций ожидает подтверждения источников. Проверки и границы перечислены в CHECKS.md. Этап 2 и защищённый сервер этапа 3 не объявляются выполненными.

## Дополнение: ручной учёт убытков
Добавить «Ремонты → Убытки»: отрицательная сумма (−5000, положительный ввод5000 нормализуется), дата, причина, необязательный заказ. Хранить отдельные записи/журнал, исправления с причиной и защиту от повторной операции. Сумма учитывается один раз в заказе (если связана), недельном/месячном отчёте и графике; отрицательный итог явно помечается «В минусе». Материалы/оплаты не получают разрешения на отрицательные значения. Полные JSON-копии/CSV включают записи; существующие данные и старые копии остаются совместимыми. По дополнительному поручению владельца работа и проверенная публикация выполняются самостоятельно без обычных подтверждений; новые платные ресурсы не нужны.

## Общая база: поручение владельца от 04.11.2026

Владелец добавил серверную переменную `DATABASE_URL` и запросил миграцию. Подготовить отдельный FastAPI/PostgreSQL API с аддитивной Alembic-схемой, входом и ролями до открытия общей базы, серверной проверкой общих JS-правил, ревизиями и идемпотентностью, журналом и предпросмотром переноса из старого JSON/localStorage. Существующий React/Vite Static Site и локальные данные сохранить; облачный режим включается публичным адресом API, без секретов в Vite. Перенос по ID/ключам сохраняет конфликтующие серверные записи и сообщает о них. Убытки также входят в общий workspace и резервные копии.

Отдельная конфигурация `render-api.yaml` не применяется автоматически, не создаёт PostgreSQL, не меняет Static Site и не включает платные ресурсы. Документация Render проверена: внутренний URL требует совпадающего региона сервиса/БД, pre-deploy migration доступна на платных сервисах. В контейнере нет автоматических миграций при старте. Порядок backup → upgrade → закрытый admin → проверка API → подключение фронтенда → preview/commit записан в DATABASE_MIGRATION.md.

На момент начала работ скриншот не показывает сервис/адрес подключения, секрет не предоставлен облачной среде. Production-миграция и фактический перенос пользовательских браузерных записей не объявляются выполненными без подтверждённого подключения и успешных команд. Это реальный блокер публикации общей базы, не основание просить пароль в чат или помещать строку подключения в frontend.

Это расширяемая подборка популярных устройств, не полный перечень всех когда-либо выпущенных телефонов. Для остальных конфигурации уточняет владелец.
