# План реализации

Исходная версия: GitHub main 7171daef6fb4c35cfcc2b68c99b37fe053699a23. Получена через GitHub API: git clone блокируется недоступным прокси. AGENTS.md в корне отсутствует. Существующие данные — массив nomad-inventory-v1; ошибки чтения прежде подменялись стартовым товаром. Исходная сборка: установка npm ci запущена; результат будет записан в CHECKS.md.

1. Этап 1: отдельные каталог, прайс, детерминированный движок и версионированное локальное хранилище; оценка → подтверждённая закупка; фактическая продажа; полная резервная копия и проверяемый импорт; тесты и адаптивный интерфейс. Не подменять старые записи демотоваром.
2. Этап 2: разрешённые источники, импорт объявлений и анализ сопоставимости; не называть ручной прайс онлайн-мониторингом.
3. Этап 3: FastAPI/PostgreSQL, защищённые сессии и роли, серверная валидация, идемпотентный перенос. Отдельные ресурсы Render после согласования инфраструктуры. Общая база до защиты не публикуется.

Этапы 2–3 не являются условиями работоспособности этапа 1. Production и main не изменять; итоговый PR требует проверки владельца.

## Результат этапа 1
Реализованы оценщик по точному сохранённому прайсу, объяснение политики, диагностические ограничения, сохранённые снимки, подтверждённые закупки и фактические продажи с журналом и возвратами, миграция v1 с резервной копией, CSV/JSON прайса и полная JSON-копия. Каталог редактируется без правок кода; часть Android-конфигураций ожидает подтверждения источников. Проверки и границы перечислены в CHECKS.md. Этап 2 и защищённый сервер этапа 3 не объявляются выполненными.

## Уточнение владельца от 04.11.2026

- Использовать предоставленный справочник из переписки; снижение iPhone 30 000 ₸, Android без снижения. Отдельные редактируемые настройки, понятное предварительное предложение до диагностики. Не вычитать снижение из витрины и не менять исторические закупы.
- Импорт DOCX/JSON прямо с главного экрана, сопоставление точных конфигураций, отчёт неоднозначных строк. Коммерческие данные остаются в локальном хранилище и пользовательском файле, не в публичном bundle/Git.
- Новая тёмно-синяя палитра, оригинальный знак из Logobook.pdf в левом блоке, SVG favicon.
- Feature-ветка feature/owner-price-guide-navy; push и новый PR без автоматического merge main.

## Автоматическая настройка по последнему поручению владельца
Владелец поручил выполнить публикацию и настройку вместо ручного скачивания/импорта. Подготовлена защищённая ссылка: публичный AES-GCM контейнер без ключа, автоматическое локальное добавление недостающих строк при открытии. Backend и платные ресурсы не требуются. Изменение проходит тесты/PR, затем публикацию по этому поручению; в пользовательском браузере импорт выполняется только после открытия персональной ссылки.

1. Встроить раздел «Ремонты» в текущий интерфейс: заказы, типы ремонта, материалы/запчасти и их себестоимость, фактические оплаты/возвраты, статусы и журнал.
2. Добавить отчёт за период с недельной/месячной группировкой и графиком: поступления по paidOn минус материалы/прямые расходы по spentOn. Сметы не считать поступлениями, отмена заказа не стирает реальные деньги.
3. Аддитивная версия repairSchemaVersion1 внутри текущего локального v2: отдельная копия до обновления, сохранение прежнего склада/прайса/оценок, проверка данных, полный JSON и CSV. Сервер/платные ресурсы не добавлять; синхронизацию устройств не обещать.
4. Автотесты финансовых расчётов/дат/идемпотентности/миграции/восстановления, браузер 390/1440, линтер и сборка; публикация через feature-ветку и проверенный PR в рамках действующего поручения владельца завершать работу самостоятельно.
